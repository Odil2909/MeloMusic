# Melo

Melo — прототип музыкального каталога на Next.js App Router. Главная получает с сервера реальные треки, альбомы и профили исполнителей из Jamendo; страницы альбомов и исполнителей открываются по ссылкам провайдера. Каталог используется только для некоммерческой технической проверки. Melo — временное рабочее название из [конфигурации бренда](src/config/brand.ts).

Поиск по трекам, альбомам и исполнителям доступен через каталог Jamendo. Регистрация и вход используют Neon Managed Auth, а серверный слой приложения подключается к Neon PostgreSQL через Prisma ORM 7. Схема приложения хранится в `public`; `User` ссылается на существующую таблицу Neon Auth в `neon_auth`. Пользовательские подборки и воспроизведение пока не подключены. API Jamendo и лицензия каждой композиции не дают автоматического разрешения на коммерческий музыкальный сервис.

## Требования

- Node.js 20.19+, 22.12+ или 24+
- npm 10 или совместимая версия

## Установка и запуск

Установить зависимости из lock-файла:

```sh
npm ci
```

Запустить dev-сервер:

```sh
npm run dev
```

Откройте <http://localhost:3000>. Проверить API доступности можно по адресу <http://localhost:3000/api/health> или командой:

```sh
curl -i http://localhost:3000/api/health
```

Ожидаемый ответ: HTTP `200`, `Content-Type: application/json; charset=utf-8`, тело `{"status":"ok"}`.

## Проверки и production-запуск

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run start
```

`npm run start` запускает уже собранное приложение. Запускайте его после успешного `npm run build`.

Миграции Prisma применяются командой `npm run db:migrate:deploy`. Она использует прямой `DATABASE_URL_UNPOOLED`; приложение использует pooled `DATABASE_URL`. Локальная разработка схемы — `npm run db:migrate:dev`. Порядок настройки переменных окружения в Vercel описан в [отдельной инструкции](docs/vercel-database-setup.md).

## Переменные окружения

Для серверных маршрутов каталога нужен зарегистрированный Jamendo `JAMENDO_CLIENT_ID`. Скопируйте `.env.example` в `.env.local` и задайте переменную локально. `PORT` используется только отдельным проверочным скриптом этапа 1. Не публикуйте клиентский ID и не используйте публичный тестовый ID для приложения.

Neon CLI заполняет `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `NEON_BRANCH`, `NEON_AUTH_BASE_URL` и `NEON_AUTH_JWKS_URL` после авторизации и `neon deploy`. Для Next.js-сессий также нужен `NEON_AUTH_COOKIE_SECRET`; локальный секрет уже создаётся отдельно и должен быть задан в окружении каждого deployment. Его можно создать командой `openssl rand -base64 32`. Prisma использует `@prisma/adapter-neon` и pooled `DATABASE_URL` во время запросов приложения; `DATABASE_URL_UNPOOLED` нужен CLI для миграций. Neon Auth управляет таблицами `neon_auth`, включая email/password credentials; Prisma описывает `User` для связей и не хранит пароли. Для работы приложения не нужен `service_role` ключ.

После входа в аккаунт Neon примените сервисы, описанные в `neon.ts`:

```sh
npx neon@latest login
npx neon@latest deploy
```

Чтобы передать переменные Node-скрипту прототипа, задайте их в текущей оболочке или запустите Node с `--env-file`:

```sh
node --env-file=.env.local scripts/verify-music-api.mjs "lofi"
```

Файл `.env.local` исключён из Git. Не добавляйте реальные секреты в исходники, README или другие документы. Инструкции по прототипу и ограничению коммерческого использования находятся в [docs/music-api-testing.md](docs/music-api-testing.md).

## Структура

```text
src/
  app/                 App Router, страница, глобальные стили и health route
    search/            серверная страница поиска по каталогу
    auth/              формы входа и регистрации
    account/           профиль и выход из аккаунта
  components/
    home/              состояния каталога и повторная загрузка
    layout/            оболочка приложения, навигация, шапка и отключённый плеер
    music/             карточки альбомов и артистов, строки треков
    player/            визуальные элементы управления плеером
    ui/                иконки, кнопки и изображения с fallback
  config/              временное название и настройки бренда
  features/home/       серверная загрузка главной и изолированные Stage 3 fixtures
  features/search/     поиск по Jamendo с состояниями загрузки и ошибок
  features/auth/       формы авторизации
  lib/neon/            серверный Neon Auth-клиент
  lib/db/              singleton Prisma Client для Neon Postgres
  generated/prisma/    генерируемый Prisma Client (не хранится в Git)
  proxy.ts             защита аккаунта с Neon Auth в Next.js
prisma/                схема приложения и аддитивные миграции
prisma.config.ts       Prisma CLI и внешняя схема Neon Auth
docs/vercel-database-setup.md  DATABASE_URL для Vercel
public/
  images/              оригинальные локальные демонстрационные обложки
  icons/               локальные значки
docs/                  материалы исследования API этапа 1
scripts/               отдельный проверочный прототип этапа 1
```

## Статус этапов

- **Этап 1 — исследование API:** отчёт и инструкции сохранены в `docs/`; для коммерческого каталога провайдер пока не выбран. В `scripts/` оставлен изолированный тест Jamendo.
- **Этап 2 — основа приложения:** Next.js App Router, строгий TypeScript, Tailwind CSS, ESLint, metadata, health route и команды проекта.
- **Этап 3 — интерфейс:** тёмная дизайн-система Melo, адаптивный layout, локальные обложки, типизированный демо-каталог и интерфейсные состояния.
- **Этап 4 — серверная интеграция:** read-only адаптер Jamendo и внутренние API-маршруты; секрет остаётся на сервере.
- **Этап 5 — главная и поиск:** реальные ответы Jamendo, альбомы с датами провайдера, артисты, жанры с доступными треками, поиск по существующему API, fallback изображений, загрузка, ошибки и пустые состояния.
- **Этап 6 — Neon backend:** Neon Postgres и Managed Auth, регистрация, вход, серверная сессия и выход из аккаунта. `/api/health/neon` проверяет подключение к базе. Библиотека и пользовательские плейлисты ещё не подключены.
- **Позднее:** выбор лицензированного источника аудио, настоящее воспроизведение, библиотека и пользовательские плейлисты — только в отдельных этапах.

Схема главной, live-проверки и ограничения разделов описаны в [отчёте этапа 5](docs/music-home-integration.md). Серверные маршруты и ограничения Jamendo описаны в [документе интеграции](docs/music-api-integration.md).

В проекте пока нет реального воспроизведения, пользовательских плейлистов, платежей или сохранения избранного.
